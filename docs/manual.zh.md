## 0. 先读这一页

**它是什么**：一块指甲盖大小的 BLE 传感器用胶泥/支架刚性固定在弓把或配重杆上，以 3332 Hz 采样 IMU，
片上算姿态，再以约 1110 Hz 把 20 字节实时帧发给浏览器；浏览器（Chrome/Edge）本地跑仪表盘、撒放识别、
轨迹回放和评分。**不需要账号，不需要云端**，断网也能用。

**它能回答的问题**

- 我举弓/瞄准时机瞄点的浮动有多大？（Pin Float 靶面轨迹 + Float Score）
- 我的弓是不是歪了？cant（侧倾）稳定吗？（数字水平泡 + cant 走势）
- 我每一发的撒放和跟随动作质量如何？（分项评分 + 相位着色轨迹）
- 这次练习和上次比进步了吗？（会话自动分组 + 趋势 + 逐箭记分）

**它不能做的事**

- 不是测速仪：箭速只能靠你填的弓配置估算；
- 不测靶环：靶面成绩要你自己点选录入；
- **不能识别"任何"撒放**：检测是"加速度 + 角速度 + 不应期"三条硬门槛，
  用缓冲气缸类撒放训练器空放时，默认阈值会完全抓不到（解法见 §8）；
- 不是安全设备，不参与任何安全判断。

**最小可用清单**：传感器一块（已烧 v0.1.0）+ 电池 + Chrome/Edge + 一个本地 HTTP 服务。
不用装 App、不用注册。

## 1. 系统全景

### 1.1 硬件组成

| 部件 | 规格 |
|---|---|
| MCU / 无线 | Seeed XIAO nRF54L15 Sense（nRF54L15，BLE 5.x，TX +8 dBm） |
| IMU | **LSM6DS3TR-C**，6 轴（加速度 ±16 g / 陀螺 ±2000 dps），ODR **3332 Hz**，FIFO 水位中断 |
| 麦克风 | 板载 PDM 数字麦克风（16 kHz），固件只上报**峰值包络字节**，不是录音 |
| 电池监测 | 标准 BLE 电池服务（BAS），引脚 `P1.14`，分压 ×2 |
| 调试器 | 板上 SAMD11（CMSIS-DAP v2），同一 USB 口枚举出 `COM3` |
| LED / 按键 | 单颗用户 LED；单颗按键（**按一下 = 一次零点标定**） |

### 1.2 数据流

```text
IMU 3332 Hz ──FIFO──► 固件：3 样本平均 → 20 B 实时帧 @1110 Hz ──BLE──► 浏览器
                         │                                              │
                         ├─ 撒放检测（阈值 + 陀螺 + 800 ms）              ├─ 实时仪表盘 / 姿态 / 曲线
                         ├─ 冻结 1000 点片上轨迹（52/104/208 Hz）          ├─ 撒放事件 → IndexedDB → 已存箭
                         └─ 终身计数 / 100 条待传队列                      └─ Float Score / 记分 / 复盘
```

### 1.3 两处"大脑"的分工

- **固件（设备端）** 负责：采样、姿态融合、**撒放判定**、计数、轨迹缓冲、电源管理。
- **浏览器（App 端）** 负责：显示、评分、存储、复盘、导出、云端同步。
- 关键推论：**"有没有检测到撒放"是设备决定的**，App 只负责把设备说的事记下来。
  所以排查"打了箭没记录"时，先看设备计数，再看 App（§14.3）。

### 1.4 你手上设备的状态基线

- 固件 **v0.1.0**（不是仓库 HEAD）。上游 `docs/` 描述的是 HEAD，涉及轨迹长度、
  命令错误码、睡前落盘等行为时，请以本手册 §4.4 的差异表为准。
- 广播名 **`OpenFloat-463F`** 是编译期常量：**所有同固件的板子都叫这个名字**，不是每块板不同。
  多块板同场时请靠"一次只开一块"来区分。
- **只允许 1 条 BLE 连接**（`CONFIG_BT_MAX_CONN=1`）：浏览器连着时，任何 Python 脚本都连不上；
  反之脚本连着时浏览器必掉。所有排查工具都受这条约束。

## 2. 快速开始

### 2.1 已有设备：15 分钟

1. **唤醒**：拿起板子用力晃 2–3 下（> 2 g）。LED 开始约 1 Hz 慢闪 = 活着。
2. **起本地服务**：在仓库根目录执行 `python -m http.server 4178`。
3. **打开页面**：Chrome 或 Edge 打开 `http://localhost:4178/`。
4. **连接**：点右上角「未连接」徽章 → 在浏览器弹窗里选 `OpenFloat-463F`。
5. **确认数据**：徽章变绿、Hz ≈ 1110、曲线开始滚动。
6. **标定**：正常持弓站好，静止 1–2 秒，点仪表盘的 **零点标定**（§7.2）。
7. **选撒放模式**：设置 → 遥测与缓冲 → 撒放模式。**真弓选 `真弓 · 12 g`**；
   用缓冲气缸撒放训练器空放选 `训练器 · 2 g`（§8.3）。
8. **打一箭**：LED 会闪一下，仪表盘「最近箭」出现一张卡片。

> 只想先看看界面？点页头的 **▶ 演示**，会推合成数据，不需要任何硬件。

### 2.2 从零开始：约 1 小时

按 §3（焊接/安装）→ §4（烧固件）→ §5（连接）→ §7（标定）的顺序做。
其中固件烧录约 10 分钟，工具链安装是大头（自己编译才需要，见 §4.3）。

### 2.3 第一次射箭前检查

- [ ] LED 慢闪（设备醒着）
- [ ] App 徽章已连接、Hz ≈ 1110
- [ ] 撒放模式 = 真弓
- [ ] 已做零点标定，气泡显示 `水平/Level`
- [ ] 传感器用手晃不动（§3.5）
- [ ] 电池 > 30%（页头电池徽章）

## 3. 硬件

### 3.1 清单与规格

| 物料 | 说明 | 备注 |
|---|---|---|
| XIAO nRF54L15 Sense | 主控 + IMU + 麦克风 | 上游要求 Sense 版（带 IMU/麦克风） |
| LiPo 电池 3.7 V | 上游建议 ~70 mAh **带保护板**；实测用 402535（≥200 mAh） | 手焊到 `BAT+`/`BAT-` |
| 安装胶泥/支架 | 可移除胶泥、阻尼扎带、5/16"-24 稳定杆座 | 一致性直接影响数据质量 |
| USB-C 数据线 | 烧录 + 调试 | 必须能传数据，不是纯充电线 |

### 3.2 电池与供电

- 焊线**必须核对极性**；上电后先摸温度，板子或电池发烫立即断电。
- 实测：纯电池满速流 **约 2–3 小时**（100 s 掉 1%）；上游明确"电池寿命尚未表征"。
- **插着 USB 时电池仍在线**，所以"拔插 USB"不会让芯片断电复位（排查时要记住这一点）。
- 长期不用：发 `autosleep:1` 或直接拔电池（`autosleep:0` 会持续耗电）。

### 3.3 外壳、五金、天线净空

- 固定螺纹：**5/16"-24 UNF × 5/8" 内六角**（配重/稳定杆标准螺纹）。
- 接触面垫 **0.5–1 mm TPU** 减震；电池仓垫 **1 mm 泡棉**，避免冲击磨破电池皮。
- 电池放**安装点另一端**做配重，尽量不改变弓的平衡。
- **天线净空**：本机工程建议天线端 10 mm 内不要有金属（⚠️ 这是经验建议，不是上游规格）。
- 外壳目前仍是进行中状态（仓库只有 fit-test 本体），可先裸板 + 胶带/胶泥验证。

### 3.4 安装方式与位置选择

- 上游设计目标：小到能装在**弓把、稳定杆或附件轨**上，且不改变弓的平衡。
- 安装必须**刚性、可重复**：任何形变/相对位移都会在轨迹里表现成噪声，且会让 cant 零点漂移。
- 推荐顺序：配重/稳定杆端（螺纹座）→ 弓把附件孔 → 扎带固定。哪个位置信噪比最好，
  上游仍是开放问题，用 §3.5 的方法自己比。
- **6 种安装方向预设只改 3D 预览，不改数据**（详见 §7.3）。刷预编译固件的用户，
  数据侧永远是"预设 #1"的映射，所以**优先靠机械安装去凑标准姿态**：板子绕弓的前向轴转 90°。

### 3.5 安装后检查清单（含重复性验证）

1. 用手猛拽/晃：不能有相对位移。
2. 打 6 发后再看零点偏移有没有漂：漂了 = 安装位移，重装并重新标定。
3. **重复性验证**：同一位置装两次，每次各打 6 箭，比较两次的 Float Score 与 cant 一致性。
4. **换孔对比**：换一个孔位重复第 3 步，回答"哪个位置信噪比最好"。

1. LED 约 1 Hz 慢闪；
2. BLE 扫描能看到 `OpenFloat-463F`（§15.1 的 `ble_scan.py`）；

### 4.4 v0.1.0 与 HEAD 的差异（决定你要不要升级）

> 一句话：**v0.1.0 能用；HEAD 更可靠、数据更完整，但不会让"检测不到撒放"变好。**

| # | 差异 | v0.1.0 的实际行为 | 对你的影响 |
|---|---|---|---|
| 1 | 轨迹分片计数是 u8 | 满 1000 点时回绕，**回放只剩约 306 点 / 5.9 s** | 断连期间补传的轨迹会明显变短；连着浏览器时不受影响 |
| 2 | 没有 `tracetimed` / `tracereq2` | 每次轨迹补传先白等约 3 秒才落到 `tracereq` | 日志出现两条 fallback 属**正常**，不是故障 |
| 3 | `shotset` / `shotreset` 连带改 shot ID | 修正计数后旧轨迹 ID 会对不上 | 计数只能"差分"用 |
| 4 | `thresh:nan` 被接受 | 撒放检测**静默关死到重启** | 别手滑发怪值（§8.6） |
| 5 | 睡前不落盘 | 自动深睡前可能丢最后一发/刚改的参数 | 收工前等 ≥5 秒（§13.5） |
| 6 | 20 B 实时帧无陀螺 | CSV 里 `gx/gy/gz_dps` 恒 0、`uptime_us` 恒空 | 正常现象，不是 bug |
| 7 | 6 种安装方向只改预览 | 数据侧固定是预设 #1 | 只能靠机械安装去凑（§7.3） |
| 8 | 轨迹落盘超 4 KB 单值上限 | "断电后还能回放"基本别指望 | 想要就编 HEAD（4 条 RRAM 轨迹） |
| 9 | 命令错误回执少 | **写命令没报错 ≠ 设置生效** | 判生效只能看行为/日志 |

**建议升级到 HEAD，如果你**：需要断连记录后靠固件轨迹复盘、需要断电保留最近 4 发轨迹、
会打到几万发、在意睡前落盘。

**不必升级，如果你**：只是练撒放/看实时数据（v0.1.0 实测 1113 Hz、0 丢包）、
不想装 10–15 GB 工具链、没有 SWD 经验（**没有 OTA**，升级只能插调试探针）。

> 顺序警告：**先升级浏览器端，再刷固件。** 反过来"新 App + 老固件"是安全组合。

### 5.4 状态徽章与关键日志

| 徽章文字 | 含义 |
|---|---|
| 未连接 / `Disconnected` | 初始或手动断开 |
| `BLE OpenFloat-463F` | 已连接 |
| `演示数据流`（Demo stream） | 演示模式（合成数据，非真实设备） |
| `BLE reconnecting...` | 掉线自动重连中 |
| `NN%` | 设备电量（来自标准电池服务） |

日志（设置 → 诊断与日志，最新在最上面）里最该认识的几行：

| 日志 | 含义 |
|---|---|
| `BLE notifications subscribed.` | 订阅成功，但还没有数据帧 |
| `BLE frames flowing.` | 收到第一帧（链路真正通了） |
| `No BLE frames after 2s — re-sending start.` | 连上但没数据，App 自动补发 `start` |
| `Shot #N (id X) peak ~Y g` | **设备检测到撒放**，开始入库 |
| `Shot metadata saved; ...` | 元数据已落库 |
| `Browser trace saved for shot ID ...` | 浏览器轨迹冻结完成 |
| `No timed trace response; trying extended recovery.` 等两条 | v0.1.0 的轨迹降级，**正常** |
| `Offline save error: ...` | 本地写库失败 |
| `BLE frame not decoded (N bytes): ...` | 帧格式不认识（固件/前端版本不匹配） |

### 5.5 断线与自动重连

- 掉线后 App 自动重试 **6 次**，间隔约 1/2/4/8/8/8 秒；成功则恢复，失败回 `Disconnected` 等你手动重连。
- 固件侧掉线后会在 250 ms 起重启广播，所以通常能自己连回来。
- 手动点徽章断开则不再自动重连。
- **重连会补传**设备缓存的已存箭（`Uploading N` 指示器会倒计时）。

## 7. 标定

### 7.1 原则：先轴向、后零点

轴向不对时，零点标定也能让读数变成 0，但之后 cant/pitch 符号全是错的，评分和 3D 会"看起来正常、实际反了"。

### 7.2 零点标定步骤

1. 机械固定好，确认实时率 ≈ 1110 Hz。
2. **轴向粗验**：弓按正常射箭姿态竖好，把弓顶往瞄准器方向倾 →
   `Cant`（roll）应变正，3D 弓同向倾斜。反了或轴互换了见 §7.3。
3. 站好，弓按正常射击姿态（含你惯用的 cant），**静止 1–2 秒**让姿态融合收敛。
4. 点仪表盘 **零点标定** → 确认。
5. 判据：`Cal Roll`/`Cal Pitch` 立刻 ≈ 0.0、气泡居中显示"水平"、事件日志出现
   `Zero calibration requested. Bow level set at Cant: … Pitch: …`。
6. （可选）**标定航向**：只写浏览器本地偏移，纯显示、不进评分、会漂。
7. 断连重连 / 断电重启，确认偏移自动恢复。

> ⚠️ **设备上的物理按键按一下就等于一次零点标定**（按下沿触发）。调试时别误按。

**零点标定到底存了什么**：只存 **roll 和 pitch** 偏移（int32 毫度，写进设备 RRAM）；
**yaw 不持久化**，只用于显示。再标一次会替换上一次，没有"恢复出厂"，只能对着当前姿态重标。

### 7.3 安装方向与 3D 对齐：数据 vs 显示

| 区域 | 改什么 | 影响数据？ |
|---|---|---|
| 传感器安装（6 预设 + 自定义 + 引导设置） | 仅 3D 预览的映射示意 | ❌ **要改数据必须重编固件** |
| 3D 模型显示（旋转/反转/交换/忽略航向） | 3D 图怎么画 | ❌ 纯显示 |
| 零点标定 / cant_offset / pitch_offset | 角度零点（存设备 RRAM） | ✅ 改数据（影响读数与评分） |
| 标定航向 / 忽略航向 | 浏览器本地 yaw | ⚠️ 仅显示 |

6 个预设的含义：

| 预设 | 物理姿态 | 数据侧映射 |
|---|---|---|
| Current firmware mount（默认） | 板子绕弓前向轴转 90° | `X, −Z, Y` |
| Current mount, inverted sign | 同上但翻面 | 符号反转 |
| Face out, USB up / down / left / right | 元件面背弓，USB 朝不同方向 | 恒等 / 绕 Z 180° / ∓90° |

**刷预编译固件的用户**：数据侧固定使用第一个预设，所以**优先靠机械安装凑出标准姿态**；
改映射需要重编固件（`MOUNT_ROT_X_SIGN` 与 `apply_mount_rotation()`）。

### 7.4 cant / pitch / yaw 与气泡

- `Cant` 是已经减掉零点偏移的 roll，显示前过 80 ms 一阶低通（模拟水平泡黏度）。
- 气泡：`|cant| ≤ 容差` → `水平`；≤3×容差 → 琥珀 + 左/右倾；更大 → 红。
- `Pitch` 同理减偏移；`Yaw` 减本地零并绕 ±180° 回卷。
- 量程/容差在仪表盘"调整水平泡设置"里调：量程越大越不敏感，容差决定"水平"的宽容度。

### 7.5 标定维护

- 每次拆装/碰撞/换弓后重新标定。
- 如果 cant 反复漂移，先怀疑安装位移（§3.5），不要靠反复标定掩盖。
- 3D 图方向不对但数值对 → 只改"3D 模型显示"里的开关，**不要动映射**。

## 8. 撒放检测与阈值

> 这一章是"打了箭没记录"的根本原因所在，值得完整读一遍。

### 8.1 设备怎么判断"这是一次撒放"

固件要求**同一个 0.9 ms 平均帧**上三条同时成立：

| # | 条件 | 数值 | 能调吗 |
|---|---|---|---|
| 1 | 加速度向量模长 > 阈值 | 默认 **12.0 g**，**含重力** ⇒ 实际需要约 **11 g 净冲击** | ✅ `thresh:`，2.0–30.0 g |
| 2 | 陀螺向量模长 > 1.5 rad/s | **85.9 °/s** | ❌ 硬编码，无命令可调（HEAD 也一样） |
| 3 | 距上次撒放 > 800 ms | ≈1.25 发/秒上限 | ❌ 编译期常量 |

命中后：计数 +1 → LED 亮 120 ms → 入 100 条待传队列 → 冻结片上轨迹。

几个容易误解的细节：

- **削顶不影响检测**：BLE 帧里加速度是 int8（±12.7 g 削顶），但检测用的是未削顶的内部 float。
  所以 App 里已检测到的箭，峰值必然显示成 ≈12.7 g——**不要用回放峰值判断"离阈值多近"**；
  反过来，**App 显示 8 g 就是真 8 g**。
- **0.9 ms 帧平均会削弱亚毫秒尖峰**：0.4 ms 的尖峰要被平均掉约 70%。真弓冲击通常 2–5 ms，
  影响可忽略；硬碰硬反而容易被抹平。
- **阈值不是一个固定物理量**：弓种、安装位置、箭重、稳定杆、射手风格都会改变峰值。

### 8.2 真弓 vs 撒放训练器

| 量 | 真弓（复合/反曲） | 缓冲气缸撒放训练器（KIS 类） |
|---|---|---|
| 冲击峰值 | 20–80 g，2–5 ms | **2–12 g**，5–20 ms |
| 撒放瞬间角速度 | 200–1000 °/s | 能过 86 °/s（实测） |
| 过 12 g 门 | 通常可以 | **不行** ← 这就是"空放完全没记录"的原因 |
| 真实样本 | 峰值约 15.9 g / 约 200 °/s | 2 g 阈值下可稳定触发 |

**结论**：用训练器空放必须把阈值降到 2 g 左右；用真弓必须回到 12 g。

### 8.3 两档预设（本仓库新增）

位置：**设置 → 遥测与缓冲 → 撒放模式**

| 按钮 | 效果 |
|---|---|
| `真弓 · 12 g` | 阈值 = 12.0 g，适合真弓 |
| `训练器 · 2 g` | 阈值 = 2.0 g（固件下限），适合缓冲气缸训练器空放 |

- 点按钮会立刻改滑块、下发 `thresh:` 到设备、并持久化到浏览器设置。
- 阈值 **< 4 g** 时出现琥珀色警告：拿起放下设备、碰到弓、空放训练器都可能被记成一箭。
- 手动拖滑块也可以；但按钮只在"滑块值 = 预设值"时高亮，不会假装成 12 g。
- **低阈值采集会打上 `release_mode: "trainer"` 标记**：已存箭/最近箭显示 `Trainer` 徽章，
  可用「隐藏训练器记录」一键过滤（只影响显示，数据仍在库里和导出里）。
- 换回真弓**记得点回 `真弓 · 12 g`**，否则会不停冒出假箭。

### 8.4 阈值标定流程（推荐做法）

1. 先用 `训练器 · 2 g` 打 3–5 发，确认能记录。
2. 打开已存箭，查看这些记录的 **Peak G**（或 Console 读 `peak_g`，见 §14.3）。
3. 把训练器预设的阈值定在**实测峰值的 60–70%**（例如峰值 5 g → 3–3.5 g）。
   比 4 g 低就仍会被标成 Trainer，语义一致。
4. 真弓则用 12 g 起步；如果高能量复合弓反复漏检，可以试 13–16 g。

### 8.5 漏检与误触发怎么判断

| 现象 | 可能原因 | 处置 |
|---|---|---|
| 空放完全没记录（`Shots:` 不动、日志无 `Shot #`） | 阈值太高（训练器最常见） | 降到 2 g 试验（§14.3） |
| 降到 2 g 仍没记录 | 角速度没过 86 °/s（极少见）或阈值被写成 NaN | 重启设备恢复 12 g 后重试；仍不行则需改固件 |
| 放下/碰撞被记成箭 | 阈值太低 | 抬高阈值，或只在训练会话用低阈值 |
| 一次撒放记成多箭 | 不应期 800 ms 没合住（罕见） | 记录下现象，属判据噪声 |
| 真弓也偶尔漏检 | 安装位置离冲击源太远/减震太多 | 换位置（§3.5）或降阈值到 10 g 试 |

### 8.6 阈值的归属与两个坑

- **v0.1.0 的 `thresh` 不持久化**：设备睡醒/复位回 12 g。
  但 **App 每次连接都会用滑块值覆写设备**——所以"设备跟着浏览器滑块走"。
  **不连 App 单独打，设备就是 12 g**。
- 永远不要发 `thresh:nan` 或任何你不确定的字符串：v0.1.0 会**静默接受**，检测被彻底关死，
  只能发回 `thresh:12.0` 或断电重启恢复。
- 在 v0.1.0 上"写命令没报错"不等于"设置生效"（命令错误回执不全）。

## 9. 一次完整射箭

### 9.1 准备

1. 唤醒设备，连上 App，确认 Hz ≈ 1110。
2. 撒放模式 = 真弓；跟随动作 1.5 s（默认）；轨迹缓存 52/208（默认）。
3. 检查零点标定与气泡。
4. 有弓配置就选好（影响声学测距的箭速）。

### 9.2 射箭

正常射即可。设备检测到撒放后：

- LED 亮 120 ms；
- App 打印 `Shot #N (id X) peak ~Y g`；
- 约「跟随动作」秒后浏览器轨迹冻结并写库；
- 仪表盘"最近箭"出现卡片，`Shots:` +1。

### 9.3 记录里到底存了什么

- **元数据**：时间、设备计数/ID、峰值 g、cant/pitch/yaw、六项评分、丢包数。
- **浏览器轨迹**（连着打时）：撒放前 3.5 秒 + 跟随窗口，208/416/832 Hz 抽稀，
  带麦克风包络（全速率另存一份）。
- **固件轨迹**（断连时打的，重连后补传）：只有角度与麦克风，**不含陀螺/加速度**，
  所以**固件轨迹不产生 Float Score**，只能回放。

### 9.4 复盘

点开任意一箭进入复盘模式：

- **瞄点浮动**：靶面轨迹按相位着色（绿=保持、琥珀/红=撒放破坏、灰=跟随），
  撒放点居中，1σ 浮动椭圆，回放标记。
- **回放条**：播放/暂停、速度 0.25–4×、拖动时间码、滚轮/双指缩放 0.5–6×。
- **运动视图**：四元数/加速度/角度折线 + 麦克风条带。
- **对比**：`对比` 下拉叠加另一箭（只列有 ≥2 点轨迹的箭），青色为对比轨迹，各自按自身幅度归一。
- **声学测距（实验）**：横幅里的 `Est. Range: xx.x yds @ 280 fps (assumed)`
  是"撒放声 + 靶上撞击声"的时间差估算，括号说明用了哪把弓的箭速；
  **它不会写回你记录的靶距**。
- 拖动 `RELEASE` / `HIT` 标记可以改测距，`Export Shot` 导出该箭。

### 9.5 记分与靶面

- 记分卡按会话内的射击顺序排列，**未计分的箭保留位置**，不会被当成脱靶。
- 点 `Score next arrow` 或某支箭，在 `落点记录` 面板里选 `M`（脱靶）/`1`–`10`/`X`，
  可填距离与靶面尺寸，也可以直接在靶面上点位置（会自动换算分数，可手动修正）。
- `保存并下一支`（最后一支变 `保存并完成`）/ `清除`。
- 会话汇总会给出总分、平均、10 数、X 数、脱靶数、前后半段趋势；
  箭数 ≥ 6 且靶面设置一致时，才可能给出"cant ↔ 水平散布"这类**早期信号**（明确标注非因果）。

### 9.6 导出

- 单箭导出：复盘页 `Export Shot` 或列表行 📤 → `openfloat-shot-<id>-<时间>.json`。
- 批量：`选择箭` → 勾选 → `导出所选` → `openfloat-selected-<时间>.json`。
- 全量：设置 → 数据备份与恢复 → `导出数据`（§12.2）。

## 10. 评分（Float Score）

### 10.1 总分与分项

Float Score 是浏览器从轨迹算出的 **0–100 动作分**，写进每条记录的 `score_version`
（当前 `openfloat-float-score-v1`）。它不是国际箭联的环数，只用于纵向比较自己的动作质量。

四个分项 + 加权：

| 分项 | 字段 | 含义 |
|---|---|---|
| 保持稳定 Hold | `hold_stability` | 瞄准窗口内 roll/pitch 抖动与角速度 |
| 撒放质量 Release | `release_quality` | 撒放瞬间的角速度峰值与加速度偏离 |
| 跟随 Follow | `follow_through` | 撒放后是否安静、有没有多余位移 |
| 水平一致 Level | `level_consistency` | cant 的绝对偏移与稳定性 |

**射箭记录**：`0.40·hold + 0.24·release + 0.22·follow + 0.14·level`。
**hold/训练记录**：`0.70·hold + 0.30·level`，`release_quality` 与 `follow_through` 恒为 `null`。

### 10.2 什么时候显示 `--`

| 场景 | 结果 |
|---|---|
| 设备撒放事件刚入库、浏览器轨迹还没冻结 | 全部分项 `null`（等 1.5 秒左右） |
| 浏览器轨迹冻结完成 | 六个分项一次性写入 |
| **固件补传的轨迹** | **完全不写分数**（只有角度+麦克风，没有陀螺/加速度） |
| hold / 手动录制 / 训练 | release 与 follow 恒 `null`，总分按 0.7/0.3 算 |
| 老记录没有 `score_version` | 用 `stability_score` 当总分（历史兼容） |

### 10.3 实时分 ≠ 存档分

仪表盘上实时刷新的分数是**即时参考**（最近 120 点、用瞬时值、权重也不同），
不要与保存后的分数逐位对照。**以存档分为准。**

### 10.4 为什么 release 常常是 0、分数上限在哪

`release_quality = 100 − 撒放窗角速度峰值·0.9 − 撒放窗加速度偏离·18`（单位 dps / g）。
真弓撒放的角速度峰值 500–1300 dps、加速度偏离 10–24 g，训练器也有 75–130 dps / 4–7 g，
两项扣分加起来远超 100 ⇒ **这一项对任何真实撒放都恒为 0**。

权重是 `0.40 hold + 0.24 release + 0.22 follow + 0.14 level`：

- `release = 0` ⇒ 最多只能拿 76；
- `follow` 用同类系数（`−平均角速度·0.65 − 位移·8`），也经常归零 ⇒ **实际上限约 54**；
- 作者自己的 6 条真弓采集（内置演示箭）存分就是 **39–47**，release 全 0。

所以：**40 分上下的总分是这套量表的正常区间**，不等于"射得烂"。
想看动作好坏，用 `hold_stability`（保持稳定）、`level_consistency`（cant 一致）和**同装置趋势**；
训练器场景更要注意 hold 窗——撒放前 1.5 秒还在动，hold 会直接掉到个位数。

### 10.5 怎么用分数训练

- 看**趋势**而不是单发：会话里的 `趋势` 与 `平均浮动` 才有意义。
- 分项最低的那项就是"反复出现的问题"，训练页的自适应推荐也是按这个挑 drill。
- `Stability` 字段有两套口径（浏览器箭 = hold stability；hold/录制 = 逐点角速度均值），
  **不要跨类型比较**。

### 10.6 v3 预览分（2026-10-20 加入，与 Float Score 并排显示）

仪表盘的「最近箭」、已存箭列表和复盘横幅里，Float Score 旁边会多一个 **`v3`** 数值。
它是新一代评分模型的预览，**不改动也不替代原来的 Float Score**。

**为什么要有 v3**：原来的评分要用角速度，而实时帧里没有陀螺仪，
`rotDps` 是用四元数差分算出来的，量化底噪约 **17–19 °/s**——这个噪声会固定扣掉约 10 分，
跟你的动作好坏无关（所以旧分都挤在 40 以下）。v3 只用角度，绕开了这个问题。

| v3 指标 | 窗口（相对撒放） | 含义 |
|---|---|---|
| 保持晃动 holdSway | −750 ~ −50 ms | 去趋势后的瞄准微晃（°） |
| 慢漂 aimDrift | 同上 | 掉弓臂/塌弓的漂移速度（°/s） |
| 撒放扭转 releaseTorque | −20 ~ +100 ms | 撒放瞬间的侧滚（°，反曲真弓才计入总分） |
| 跟随平滑 followSmooth | +100 ~ +350 ms | 跟随阶段的抖动（°，含倒弓前滚的去趋势） |
| 倒弓 bow tip（仅显示） | +100 ~ +500 ms | 撒放后弓身前滚的幅度、到达 90% 的时间、单调性、峰值角速度（°，**不计分**） |
| MCRT（仅训练器诊断） | −600 ~ −60 ms | 响片声 → 撒放冲量的间隔（ms，**训练器上含活塞滞后，绝对值不可比**） |

计分用"半高斯" `100 × 2^(−(x/scale)²)`：顶部平坦（噪声不惩罚好箭），中段最敏感。
训练器模式暂时不计 `releaseTorque`（气缸冲击与弓片冲击不同源）。

> ⚠️ v3 的 scale 目前是**训练器冷启动值**（7 箭实测），不是绝对标准：
> `scale = 1.4 × 个人中位数` 的含义是"打出自家中位数的那一箭得 70 分"，
> 所以它**只能看自己的趋势**，不能跟别人比、也不能跟 Float Score 比。
> 真弓场景的 scale 需要用真弓数据重新标定，见到 `v3` 数值偏乐观属正常。

## 11. 训练页

### 11.1 三个 drill

| drill | 目标 | 练什么 |
|---|---|---|
| 稳定瞄准 Steady Aim | 80 | 完整瞄准窗口里更小更安静的浮动 |
| Level Lock | 85 | 把 cant 控制在水平容差内 |
| Settle & Hold | 80 | 结束时（最后 1/3）的控制不差于开始时 |

每个 drill 有自己的评分规则与提示语；选 drill 会把保持时长自动设成它的默认值。

### 11.2 自适应推荐

`训练重点 = 自适应推荐` 时，App 取你最近 **30 条有分的记录**（含射箭记录），
比较"保持稳定"与"水平一致"哪个更弱，给出基线分与 +5 的目标（上限 95），并推荐对应 drill。
示例数据和演示训练不参与统计。

### 11.3 一次训练流程

1. 选 drill/时长 → `开始训练`。
2. **5 秒准备倒计时**（配提示音）→ `Draw Your Bow` 提示。
3. 保持阶段：靶面 + 实时浮动 + cant 角标 + 剩余秒数。
4. 以下任一情况会中断并提示：离开训练页、页面隐藏、连接变化、样本间隔 > 1 秒。
5. 结束时出结果卡：得分、平均 cant/pitch 偏差、最大浮动幅度、教练建议。

### 11.4 保存与区别

`保存本次训练箭` 会写一条 `capture_kind: "hold"` 的记录（标签形如 `稳定瞄准 (10s)`）：

| 维度 | 射箭记录 | 训练 hold |
|---|---|---|
| 触发 | 设备检测到撒放 | 你点开始训练 |
| 类型 | `arrow` | `hold` |
| 释放/跟随分项 | 有 | 恒 `null` |
| 进记分卡 | 是 | **否** |
| 复盘相位 | 有 hold/break/release/follow | 只有"hold recording" |

## 12. 数据管理

### 12.1 本地库

浏览器 IndexedDB（库名 `openfloat_db`）六张表：`bow_profiles`、`sessions`、`shots`、
`shot_traces`、`sync_queue`、`session_overrides`。
所有写入以事务提交，提交成功才通知界面刷新。

关键字段（`shots`）：`capture_kind`（arrow/hold）、`release_mode`（bow/trainer）、
`device_shot_id`、`peak_g`、六个评分字段、`packet_loss_count`、`arrow_score`/`impact_x/y` 等。

### 12.2 备份与恢复

- `导出数据`：把本地所有箭、轨迹、会话设置、弓配置导出成一个 JSON 文件，
  文件名 `openfloat-backup-<时间戳>.json`，格式 `openfloat-export` v1。
- `导入数据`：默认**按主键合并**（同 id 覆盖，其余保留）；未知格式/版本不符会整体拒绝，
  不会留下半套数据。
- 单箭导出文件也能通过同一入口导入。
- 云端同步失败不影响本地导入成功。

### 12.3 示例数据

首次打开且库为空时，自动注入 **6 条真实采集**的演示箭（标记 `sample`，永不云同步），
标题带 `演示` 前缀。设置 → 演示箭 → `移除演示箭` 后不再自动注入。

### 12.4 云端同步（可选，自建 Supabase）

- 入口：页头云同步徽章 → 填 `Supabase URL` + `Anon Key` → 连接。
- 需要先在 Supabase 里执行仓库的 `supabase/schema.sql`（建表 + RLS 策略）。
- 用**匿名登录**；如果项目没开匿名登录，日志会提示去 Authentication → Providers → Anonymous 打开。
- 同步是**后台队列**：本地写入永远先成功，上传失败留在队列里稍后重试。
- 云端只存 `shots` / `shot_traces` / 弓配置等；**会话分组、会话命名、每 end 箭数只在本地**。
- **删除只删本地**，云端副本不变。
- 客户端从 CDN 动态加载 supabase-js：**离线或用不了 CDN 时同步不可用**。

### 12.5 离线

安装为 PWA 后，首次在线打开一次即可离线使用仪表盘、已存箭、复盘、指南
（3D 模型与 Three.js 都已本地化预缓存）。云端同步仍需网络。

## 13. 电源与续航

### 13.1 LED 状态表

| 状态 | LED |
|---|---|
| 上电 / 广播 / 已连接 | **约 1 Hz 慢闪**（每 500 ms 翻转；没有"已连接"专用灯语） |
| 检测到一次撒放 | **常亮 120 ms**，然后回慢闪 |
| 启动时存储恢复失败 | 反复双闪且不广播（**仅 HEAD**），30 秒后重试 |
| 深度睡眠 | **全灭** |
| 低电 | **没有低电灯语**——只能看 App 里的电池百分比 |

一句话记法：**慢闪 = 活着；闪一下 = 记到一箭；全灭 = 睡着了（晃它）。**

### 13.2 自动睡眠

| 项 | 默认 | 说明 |
|---|---|---|
| 自动休眠总开关 | 开 | `autosleep:0` 可关（台架调试常用，代价是持续耗电） |
| 断开时空闲超时 | 300 s（5 分钟） | 默认值；`sleeptime:` 可调 5–600 s |
| 连接时空闲超时 | 600 s | **硬编码**，不受 `sleeptime` 影响 |
| "还在动"判定 | 0.15 g | `sleepsens:` |
| 唤醒门限 | 2.0 g | `wakesens:` |

v0.1.0 **睡前不落盘**：自动深睡前若还有"延迟写入"的队列，可能丢掉最后一发或刚改的参数。

### 13.3 唤醒

**唯一途径是 IMU 运动中断**：拿起来用力晃 2–3 下（> 2 g）。
没有按键唤醒、没有 USB 插入唤醒、没有定时唤醒。

唤醒 = SoC 复位 ⇒ 未持久化的参数回默认（`thresh` 会回到 12 g；App 重连后会重新下发）。

### 13.4 续航与省电

- 实测满速流纯电池 **约 2–3 小时**（上游未表征）。
- 省电手段：降低实时流率（`streamrate`）、关掉轨迹缓存、缩短跟随窗口、不用时让它睡。
- 台架调试先发 `autosleep:0`，否则 5 分钟没人动就睡了。

### 13.5 收工流程

1. 停止射箭，等 **≥5 秒**（让延迟落盘走完）。
2. 在 App 里手动断开（点状态徽章）。
3. 长期不用：发 `autosleep:1` 或拔电池；`autosleep:0` 会一直耗电。
4. 建议每周导出一次备份（§12.2），浏览器清缓存/换设备会丢本地库。

## 14. 故障排查

### 14.1 连不上 / 扫不到设备

| 检查 | 处置 |
|---|---|
| LED 是否慢闪 | 全灭 = 已深睡，**晃 2–3 下**唤醒 |
| 是否有别的程序连着 | 设备只允许 1 条连接：关掉 Python 脚本/nRF Connect/另一个浏览器标签 |
| 页面地址 | 必须 `https://` 或 `http://localhost`；局域网 IP 不行 |
| 浏览器 | Firefox/Safari/iPhone 全都不支持，用桌面 Chrome/Edge |
| Windows 蓝牙 | 确认系统蓝牙开着；必要时关开一次适配器 |

### 14.2 连上但没数据（Hz = 0）

1. 看日志有没有 `BLE notifications subscribed.` 但没有 `BLE frames flowing.`
   → 设备可能在睡的边缘或广播已停，断开重连一次。
2. 是否被别的连接抢走（单连接）。
3. 固件是否在启动恢复失败状态（HEAD 会双闪且不广播）。

### 14.3 打了箭但完全没有记录（最常见）

**先分清是"设备没检测到"还是"App 没记下来"**：

| 观察点 | 设备没检测到 | App 侧问题 |
|---|---|---|
| 日志有无 `Shot #N ... peak ~Y g` | ❌ 没有 | ✅ 有 |
| 仪表盘 `Shots:`（设备终身计数） | 不动 | 会动 |
| 日志有 `Offline save error` / `already saved at` | ❌ | ✅（写库失败/判重） |
| 设备 `pending`（待传队列） | 0 | 可能 >0 |

**最常见的三种原因**：

1. **用了缓冲气缸撒放训练器空放**（默认 12 g 抓不到）→ 切到 `训练器 · 2 g`（§8.3）。
   - 判断法：把阈值拖到 2.0 g 再空放 3 次。有记录 = 就是阈值问题；
     仍没有 = 卡在 86 °/s 陀螺门限（很少见）。
2. **阈值被改坏了**：滑块位置、或曾经发送过 `thresh:nan` ⇒ 检测被静默关死。
   → 点 `真弓 · 12 g`，必要时断电重启。
3. **打箭时其实没连上**：单连接被脚本占用、页面后台被系统休眠、设备自动睡了。
   → 看 `Shots:` 有没有动；没动了就是没连上（但设备自己会缓存，重连后会补传）。

**确认能记录之后，再看是不是"记录有了但看不到"**：最近箭只显示 5 条、会话按 30 分钟分组、
「隐藏训练器记录」是否被勾上。

### 14.4 有记录但没有分数 / 轨迹很短

| 现象 | 原因 |
|---|---|
| Float 显示 `--` | 固件补传的轨迹（只有角度+麦克风）不产生分数；或浏览器轨迹还没冻结 |
| 轨迹回放只有 ~306 点 / 5.9 s | v0.1.0 的分片回绕 bug（§4.4 第 1 条），升级 HEAD 可解 |
| 复盘日志有两条 `No timed trace response...` | v0.1.0 必然的三级降级，**正常** |
| 撒放后没有轨迹 | `轨迹缓存速率 = Off`；或连接刚好断开 |

### 14.5 数据看起来不对

| 现象 | 排查 |
|---|---|
| cant 一直是 0 / 不随弓倾斜 | 没标定，或轴向不对（§7） |
| cant/pitch 符号反了 | 安装方向问题：机械翻转或重编固件；纯显示错就改"3D 模型显示"的开关 |
| 数值对但 3D 图方向错 | 只改显示开关，别动映射 |
| 轨迹噪声大/零点漂移 | 安装松动（§3.5），重装 + 重标定 |
| 一打就掉线 | 电池/焊点/天线被金属挡住；用 `shake_test.py` 做冲击测试 |
| Shots 数字很怪（如 47） | 那是**设备终身计数**；bring-up 晃动会贡献假计数。正式测前可 `shotset:0` |

### 14.6 其他

| 现象 | 处置 |
|---|---|
| 蓝牙名永远是 `OpenFloat-463F` | 编译期常量，正常；多块板同场请一次只开一块 |
| 轨迹补传卡住 | 日志出现 `Watchdog: Stored shot upload stalled` 会自动重发 `shotdump` |
| 云端一直失败 | 检查 URL/Key、匿名登录是否开启、能否访问 CDN（supabase-js 动态加载） |
| 页面更新后行为没变 | 强制刷新（Ctrl+Shift+R）；Service Worker 缓存版本已随版本号递增 |
| 中文里夹英文 | canvas 绘制、日志、单位/品牌词是设计边界（§15.4）；按 `EN` 可切回英文 |

### 14.7 常见日志速查

见 §5.4 表格。补充两条容易吓人的：

- `No timed trace response; trying extended recovery.` + 下一条 → v0.1.0 正常降级。
- `BLE frame not decoded (N bytes): <hex>` → 帧格式不匹配，通常是前端/固件版本组合不对。

### 15.1 脚本工具（本机附带，非上游）

| 脚本 | 用途 |
|---|---|
| `scripts/ble_scan.py [秒]` | 只看广播，确认设备醒着且没被别人占用 |
| `scripts/gatt_verify.py` | 完整 GATT/电池/控制命令验证（会自动发 `autosleep:0`） |
| `scripts/shake_test.py [秒]` | 纯电池边晃边看：链路是否断、有没有复位（焊点/电池压力测试） |
| `scripts/of_dev_probe.py` | **只读**取证：读电池、计数、待传队列、帧率，不写任何命令 |
| `Open-Float-Archery/tools/openfloat_ble_client.py` | 原始数据落盘 CSV、发控制命令、`--reset-command shottrigger` 台架造一发 |
| `python scripts/verify_release_mode.py` | 浏览器端到端验证撒放模式/训练器过滤（Playwright） |

⚠️ **任何脚本连着设备时，浏览器就连不上**（单连接）。用完记得脚本退出。

### 15.2 BLE 命令速查

写法：ASCII、无换行，写到控制特征 `…-0003`。想让命令报错就用"带响应"写入。

| 类别 | 命令 |
|---|---|
| 流控 | `start`、`stop`、`streamrate:<1/2/5/10/20>` |
| 标定 | `zero` |
| 撒放 | `thresh:<g>`、`shottrigger`、`shotreset`、`shotset:<n>`、`shotack:<n>`、`shotdump` |

### 15.5 安全（请认真读）

- OpenFloat 是**实验性/爱好/教学项目，不是安全设备**，不得用于任何安全关键判断。

## 附录 B：常见问题（FAQ）

**Q：能不能不下 App 只带板子去练？**
能，但设备自己只有 12 g 阈值（`thresh` 不持久化），且断连期间的轨迹在 v0.1.0 上会变短。
建议至少把 App 开着。

**Q：为什么"最近箭"只有 5 条，是不是丢数据？**
不是。最近箭固定显示 5 条；完整记录在"已存箭"，按 30 分钟间隔自动分会话。

**Q：`Shots:` 数字和我打的数量对不上？**
它是**设备终身计数**，包含 bring-up 时晃动/碰撞产生的假计数；不是数据库条数。
正式测前可以 `shotset:0` 归零（别用 `shotreset`，v0.1.0 会连 ID 一起清）。

**Q：训练器空放能记录，但一换真弓就全是假箭？**
换回 `真弓 · 12 g` 预设。反之亦然。

**Q：能同时连手机和电脑吗？**
不能，只支持 1 条连接。

**Q：固件怎么升级？有没有 OTA？**
没有 OTA，只能用 USB + 调试探针烧（§4）。

**Q：数据在哪？换电脑怎么办？**
在浏览器 IndexedDB 里；用设置里的"导出数据"搬过去（§12.2）。

**Q：中文界面里怎么还有英文？**
canvas 内文字、日志、单位/品牌词不翻译（§15.4）。
