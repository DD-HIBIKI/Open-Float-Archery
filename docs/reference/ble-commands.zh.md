# BLE 控制命令

固件暴露了一个 BLE **控制特征值**
（`8f3f3b10-0f5a-4f4c-9a2d-000000000003`），它接受 ASCII 命令。Web
应用会在仪表盘和设置中替你发送这些命令，但你也可以使用 `tools/openfloat_ble_client.py`
之类的 BLE 工具直接发送，用于调试和验证。

---

## 数据流控制

- `start` —— 启用实时通知（同时触发一次计数同步帧）。
- `stop` —— 停用实时通知。
- `streamrate:<n>` —— 设置 BLE 实时流的分频系数：`1`、`2`、`5`、`10`
  或 `20`（约 1110、555、222、111 或 55 Hz）。

## 标定

- `zero` —— 记录当前的横滚和俯仰，并作为永久水平偏移保存到 RRAM。
  航向在浏览器中仍只用于显示，固件不会持久化它。

## 出箭检测

- `thresh:<g>` —— 撒放检测阈值，单位为 g，限制在 `2.0`–`30.0`。
- `shottrigger` —— 生成一次合成箭事件，用于台面测试检测、已存箭上传、轨迹冻结和确认通路。
- `shotreset` - 将持久化的累计箭数重置为 0，并清空已存箭积压。采集 ID 会继续递增，
  因此下一箭的 ID 会与之前保存的箭不同。
- `shotset:<n>` - 在不改变采集 ID 的前提下修正持久化的累计箭数。
  使用 `0` 到 `4294967295` 的十进制数字。
- `shotack:<n>` —— 确认箭 ID `n` 已由浏览器保存；释放其存储槽位。
  该 ID 是已存箭帧中的 32 位设备箭 ID。
- `shotdump` —— 请求上传所有已存箭积压，并附带一帧存储状态。

箭相关取值（`shotset`、`shotack` 以及三个轨迹请求命令）必须是无符号十进制数字。
空值、符号、空白、后缀以及超过 `4294967295` 的值都会被拒绝，既不改变计数，也不启动传输。
所有控制命令中的内嵌 NUL 字节都会被拒绝。有效的计数修正与重置在重启后会保留采集 ID。
累计箭数达到上限后不再增加；独立的 32 位采集 ID 仍按正常回绕继续。
确认和轨迹请求请使用事件元数据中的设备箭 ID，它可能与显示的累计箭数不同。

## 电源管理

- `wakesens:<g>` —— 唤醒加速度计阈值，限制在 `0.5`–`8.0` g。
- `sleeptime:<s>` —— 深度睡眠超时，单位为秒，限制在 `5`–`600`。
  新固件默认 300 s。
- `sleepsens:<g>` —— 保持唤醒的空闲运动阈值，`0.05`–`0.50` g。
- `autosleep:<0|1>` —— 启用或停用由静止触发的深度睡眠。

在自动睡眠之前，固件会先完成跟随动作，并保存待生效的设置、排队的箭以及已请求的轨迹。
在这段短暂的最终保存期间，若请求了响应，控制回调会以 ATT Write Request Rejected
（`0xfc`）拒绝新命令。保存失败最多重试三遍；持续出错则让传感器保持唤醒，
并在三十秒后重试睡眠。睡眠被推迟时，控制会重新打开。
物理睡眠/唤醒和回调时序仍需硬件验证。

## 轨迹缓冲区

- `tracetimed:<shot_id>` - 请求完整的已存轨迹，包含记录时序、撒放参考和校验和验证。
  支持全部 1,000 个点。
- `tracereq2:<shot_id>` - 请求未计时的兼容轨迹，使用 32 位箭 ID 和 16 位分块索引。
  支持全部 1,000 个缓冲点。
- `tracereq:<shot_id>` - 旧的传输格式，最多支持 692 个当前点。
  更新后的固件对更大的轨迹返回状态 2。浏览器会先尝试计时命令，
  再依次回退到扩展格式和旧格式。当请求的槽位不可用时，所有命令都返回轨迹状态 0。
- `bufrate:<hz>` —— 轨迹缓冲区速率：`0`、`52`、`104` 或 `208` Hz。
- `bufnvs:<0|1>` —— 切换缓冲轨迹的 RRAM 持久化。
- `followms:<ms>` —— 撒放后的轨迹冻结延迟，限制在 `0`–`3000` ms。

调参命令需要完整的值。开关和速率使用无符号十进制数字，且必须匹配列出的选项。
`sleeptime` 和 `followms` 接受有符号 32 位十进制整数；超出其规定限制的有效数字会被钳制。
`thresh`、`wakesens` 和 `sleepsens` 接受有限十进制数（包括指数形式），并保留其规定的钳制范围。
空值、空白、后缀、十六进制表示、NaN、无穷大以及转换溢出会以
ATT "Value Not Allowed"（`0x13`）拒绝，设备设置保持不变。

启动时，持久化的调参值必须具有完整的四字节记录，且落在其支持的范围内。
无效值保留固件默认值，包括一个有效且非零的流分频系数。

---

> 从应用发送的设置会缓存在本地，并在固件支持该命令时持久化到设备。
> 如果旧设备仍残留较短的持久化睡眠超时，发送一次 `sleeptime:300` 即可迁移。
